# proton-exe-starter — команды и действия GUI

Один бинарь, три точки входа — `dispatch.py` смотрит на `argv[0]` (то есть на то, под каким именем его вызвали — техника, которую использует, например, сам `busybox`: один исполняемый файл, разное поведение в зависимости от имени вызова) и подгружает нужный модуль:

| Имя вызова | Модуль | Роль |
|---|---|---|
| `equestria-proton-settings` | `main.py` | Менеджер приложений/настроек по умолчанию — открывает кнопка «Открыть настройки Proton» в `equestria-os-settings` (`mod_proton.py`). |
| `equestria-proton-run` | `launcher.py` (запускается через `proton_runner.py:main()`, строка 80) | Двойной клик по `.exe` — реальный запуск игры/программы. |
| `equestria-proton-cleaner` | `cleaner.py` | Отдельный CLI/GUI для очистки Proton-кешей (та же логика, что дублирована в `mod_proton.py` настроек — см. `equestria-os-settings/COMMANDS.md`). |

## Запуск `.exe` (`proton_runner.py:80-153`)

1. По пути к `.exe` строит стабильный `app_id = <имя_exe>_<md5-хеш-пути[:8]>` (md5 здесь используется не для криптографии, а просто как быстрый способ получить короткий, воспроизводимый идентификатор из длинного пути) — у одного и того же файла всегда один и тот же префикс, у разных файлов с одинаковым именем — разные.
2. Префикс: `~/.local/share/Equestria OS/ProtonApps/<app_id>/` (`APPS_DATA_DIR`). «Префикс» в терминологии Wine/Proton — отдельная папка, имитирующая целый диск `C:\` для одного Windows-приложения: свой реестр, свои системные папки, свои установленные библиотеки — изолированно от других приложений и от реальной системы. Если ещё не создан — `_preseed_shared_windows()` (`launcher.py:60`/`proton_runner.py:58`) подкладывает общую заготовку `windows/` (набор системных Windows-DLL, которые иначе Proton при первом запуске каждой игры скачивал/распаковывал бы заново — так все префиксы этого проекта делят одну и ту же базовую заготовку, экономя время и место).
3. Настройки конкретного приложения — JSON `~/.config/.../<app_id>.json`: `dxvk_hud`, `fsr`, `xbox_pad`, `proton_version`, `launch_args`, `virtual_desktop`, `debug_log`.
4. Переменные окружения перед запуском (`apply_game_env()`, `launcher.py:73-98` + сам `proton_runner.py:109-126`):
   * `WINEPREFIX=<префикс>` — переменная, которую понимает сам Wine/Proton: «вот тебе путь к папке, которую считать диском C:\ для этого запуска»; `GAMEID=<app_id>` — используется утилитой `umu-run` для внутренней идентификации игры (влияет, например, на подбор известных для конкретной игры патчей совместимости);
   * `DXVK_HUD=compiler,frametimes,fps` — переменная самого DXVK (слоя трансляции DirectX→Vulkan), включает оверлей поверх игры с этими тремя метриками;
   * `WINE_FULLSCREEN_FSR=1` — включает FSR (AMD FidelityFX Super Resolution — технология масштабирования изображения) на уровне самого Wine;
   * геймпад как Xbox 360 (`xbox_pad`) → **три** переменные сразу: `PROTON_PREFER_SDL=1` понимает GE-Proton/CachyOS-сборки Proton (SDL — библиотека ввода, через которую Proton видит геймпады), `PROTON_DISABLE_HIDRAW=1` + `PROTON_NO_STEAMINPUT=1` — та же цель для обычного Proton/UMU-Proton (это ровно та пара переменных, которую сама Valve включает своим внутренним конфигом «sdlinput»). Три переменные сразу, потому что заранее неизвестно, какая именно сборка Proton будет использована — нераспознанные конкретным движком переменные он просто игнорирует, лишними не мешают;
   * версия Proton (`proton_version`) → `PROTONPATH`: пусто = автовыбор (`umu-run` сам подтягивает и обновляет UMU-Proton — собственную сборку проекта umu-launcher), `"GE-Proton"` = всегда последняя сборка GE-Proton (популярная альтернативная сборка Proton с доп. патчами совместимости от сообщества, `umu-run` тоже умеет её обновлять сам), иначе — абсолютный путь к конкретной закреплённой пользователем сборке (если её удалили — переменная просто не выставляется, и игра запускается через автовыбор, чтобы не сломать запуск из-за отсутствующей версии);
   * отладка (`debug_log`) → `DXVK_LOG_LEVEL=info`, `VK_LOADER_DEBUG=warn`, `WINEDEBUG=err`, `PROTON_LOG=1` — четыре независимых переменных логирования разных компонентов стека (DXVK, загрузчик Vulkan, само ядро Wine, обёртка Proton), включаются вместе, потому что проблема совместимости обычно требует смотреть логи всех слоёв сразу.
5. Сама команда запуска — **`umu-run <exe> [доп. аргументы]`**. `umu-run` — консольная утилита проекта umu-launcher (Open Source Unified Launcher for Proton/Wine — независимый от Steam способ запускать Windows-приложения через тот же Proton, которым пользуется Steam), а не прямой вызов бинарника Proton — она сама скачивает/обновляет нужную сборку Proton и правильно настраивает окружение перед запуском. Если включён «виртуальный рабочий стол» (`virtual_desktop`) — оборачивается в `umu-run explorer.exe /desktop=EquestriaOS,<WxH> <exe> ...`: `explorer.exe` внутри Wine умеет создавать **виртуальный** экран заданного разрешения (`/desktop=<имя>,<WxH>`), в котором запускается целевая программа — полезно для старых игр, которые плохо ведут себя в настоящем полноэкранном режиме или при смене разрешения основного монитора; разрешение берётся из реального размера основного экрана (`app.primaryScreen().size()`).
6. Запуск идёт под окном сплэша (`SplashWindow` → `subprocess.Popen(cmd, env=env, cwd=<папка exe>, stdout=<лог-файл>)` — `cwd` выставляется в папку самого exe-файла, потому что многие Windows-программы ищут свои ресурсы относительно рабочей директории запуска, а не относительно своего собственного пути), лог пишется в `<APPS_DATA_DIR>/<app_id>.log`.
7. После завершения — `_migrate_windows_to_shared()` повторно: если `umu-run` только что создал совершенно новый префикс (`windows/` не существовало до запуска — то есть общая заготовка почему-то не подложилась заранее), переносит его в общую заготовку атомарным `os.rename` (та же гарантия «всё или ничего», что и везде в проекте, где встречается эта функция) — безопасно даже если что-то из игры ещё держит файлы открытыми, поскольку переименование не требует, чтобы файлы были закрыты.

## Прочее

* `mimeapps.list` пакета ассоциирует MIME-типы `.exe`/`.msi` с `equestria-os-proton-run.desktop` — это стандартный freedesktop-механизм «какое приложение открывает какой тип файла по умолчанию», тот же самый, которым определяется, что `.pdf` открывается читалкой PDF, а не текстовым редактором.
* Ни один из трёх режимов не использует `pkexec` — всё в пользовательском окружении (Wine-префиксы, кеш) не требует root.
* `cleaner.py` — см. пересечение с `equestria-os-settings/modules/mod_proton.py`: тот же набор действий (очистка шейдеров/префикса/Mesa-кеша), но как самостоятельный инструмент, запускаемый под именем `equestria-proton-cleaner`.

## Удобство для не-игрового софта (2026-09-29)

Главная жалоба, которую решает этот раздел: после установки обычной Windows-программы (не игры) единственным способом запустить её снова было находить `.exe` заново через файловый менеджер внутри скрытого Wine-префикса — то же неудобство, что и у голого Wine, и то, что в Bottles решено через сканирование ярлыков.

* **`cleaner.py` → `find_candidate_exes()` + кнопка «▶ Launch» на карточке каждого приложения.** Сканирует `Program Files`/`Program Files (x86)` внутри префикса (без разбора бинарного формата `.lnk` — искомый `.exe` почти всегда лежит там же), отфильтровывает типовой мусор инсталляторов (vcredist, dotnetfx, dxsetup и т.п.) и папку `Common Files`, отдельно помечает деинсталляторы (`unins000.exe` и подобные — Inno Setup/NSIS) видом `"uninstall"`. Меню собирается заново при каждом открытии (`aboutToShow`), а не один раз при создании карточки — список программ в префиксе может пополниться, пока окно уже открыто. Запуск — через уже установленный `equestria-proton-run <путь>` (`subprocess.Popen`, без ожидания завершения), так что получает те же настройки/сплэш/app_id, что и обычный двойной клик.
* **`gamemode`** (чекбокс в `main.py`, обрабатывается в `launcher.py`): если `gamemoderun` есть в системе (`shutil.which`), оборачивает им финальную команду запуска (`gamemoderun umu-run ...`). Не входит в `depends` PKGBUILD — осознанно опциональный инструмент, при отсутствии просто не оборачивает.
* **`upscaler_upgrade`** (чекбокс в `main.py`, обрабатывается в `apply_game_env()` в `launcher.py`): один тумблер вместо трёх переменных — выставляет `PROTON_FSR4_UPGRADE=1` + `PROTON_DLSS_UPGRADE=1` + `PROTON_XESS_UPGRADE=1` (подмена DLL апскейлера свежей версией; поддерживается в Proton-CachyOS/свежих GE-Proton, 2026). Билды Proton без этой возможности просто игнорируют неизвестные переменные — тот же принцип, что уже используется для `xbox_pad`.

**Известный несделанный долг** (см. память `proton-exe-starter-project`): `proton_runner.py` — мёртвый код, ни один из двух путей упаковки (`PKGBUILD`-скрипты и `dispatch.py` из `proton-starter.spec`) его не вызывает; решение об удалении отложено.

## "Тяжёлый" софт — MS Office / Adobe и подобные (2026-09-29)

* **`.msi`-инсталляторы** — раньше `cmd = ["umu-run", exe_path]` пытался исполнить `.msi` напрямую, что не работает: это не PE-файл, а пакет для службы Windows Installer. Теперь `launcher.py` определяет расширение и для `.msi` строит `umu-run msiexec /i <файл>` (в реальной Windows двойной клик по `.msi` делает то же самое). Добавлено в MIME-ассоциации: `mimeapps.list`, `equestria-os-proton-run.desktop`, `equestria-os-proton.desktop` (`application/x-msi`) — двойной клик и пункт меню Dolphin теперь работают и для `.msi`, не только для `.exe`.
* **`riched20`** добавлен в `DESKTOP_WINETRICKS_VERBS` — контрол форматированного текста, без которого не открывается интерфейс Word/Excel/PowerPoint (подтверждено отчётами Bottles 2026 о рабочих связках для MS Office/365). Если `desktop_profile` уже использовался раньше на этой машине — общий пул `_shared/windows-desktop/` уже создан без этого компонента и сам не обновится; нужно один раз нажать «Rebuild Template» в `equestria-proton-cleaner`, чтобы он пересобрался со свежим списком компонентов при следующем запуске десктоп-приложения.
* **`WINE_LARGE_ADDRESS_AWARE=1`** теперь всегда включается вместе с `desktop_profile` (`apply_game_env()`) — многие старые 32-битные "тяжёлые" программы (классический Photoshop, Excel с большими файлами) без этого флага сами ограничивают себя 2 ГиБ адресного пространства независимо от реальной RAM в системе; для программ, которым это не нужно, эффекта нет.
* **Честная граница возможностей.** MS Office (2016/2019/2021, включая подписку 365) — по актуальным community-отчётам 2026 года реально работает на связке corefonts+msxml6+riched20+gdiplus, ровно то, что теперь стоит по умолчанию в `desktop_profile`. Современный **Adobe Photoshop 2021+/подписной Creative Cloud** по состоянию на 2026 год не поддерживается: единственная известная сторонняя сборка (PhialsBasement/wine-adobe-installers) рассматривалась и отклонена — см. память `proton-exe-starter-project`. Старые перпетуальные версии (Photoshop CS6 и близкие) продолжают работать через обычный `desktop_profile`.
