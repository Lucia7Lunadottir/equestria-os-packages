# Equestria Unity

Нативный лаунчер Unity для Linux на PyQt6 и Equestria Qt Kit. Из каталога исходников запустите `./start.sh`. Установленный пакет предоставляет команду `equestria-unity` и ярлык меню. Сборка пакета — `makepkg`.

## Как пользоваться

Вёрстка повторяет Unity Hub: слева «Проекты», «Шаблоны», «Установки»; справа вверху «Пакеты», Unity ID и настройки.

**Проекты.** «Добавить → Добавить папку…»: выберите папку с вашими проектами (например, `~/Unity`), лаунчер найдёт все проекты внутри. Папку можно перетащить в окно. Таблица: звёздочка (клик по её столбцу поднимает избранные наверх), имя и путь (клик по имени открывает проект), версия редактора (клик по ней открывает меню версий), когда изменён, меню «⋯». Заголовки столбцов сортируют, «Версия редактора ▾» фильтрует. Предупреждение ⚠ значит, что нужной версии редактора нет.

**Новый проект.** Кнопка «Новый проект»: слева сетка шаблонов, справа панель с названием, папкой и кнопкой «Создать проект».

**Установки.** Карточки редакторов с установленными платформами, каналом выпуска (LTS и другие, по официальному каталогу), размером на диске и кнопкой «Обновить до …», когда в той же ветке вышел более новый патч. «Управление»: добавить модули, найти обновления (весь список патчей той же ветки, установленные отмечены), показать папку, удалить. «Установить редактор» открывает мастер из трёх шагов, как в Unity Hub: версия → модули → подтверждение.

**Операции.** Всё, что выполняется (установка, клонирование), видно в панели вверху окна. «Подробнее» открывает список операций: у каждой свой прогресс и своя кнопка отмены, там же очередь и недавние результаты («✓» или «✗»). Вторая установка ждёт в очереди и начнётся сама, когда закончится первая. «Журнал» показывает полный вывод.

**Unity ID и лицензии.** Страница «Unity ID» показывает карточку аккаунта (имя, почта, состояние входа) и лицензии — по карточке на лицензию, как в Unity Hub: продукт, тип, организация и срок действия. Те же карточки — в «Настройки → Лицензии». Данные берутся из `unity auth status` и `unity license status` в формате JSON.

**Вход в аккаунт внутри редактора без Unity Hub.** Кнопка Sign in, Asset Store, «My Assets» и облачные сервисы редактора спрашивают аккаунт у Unity Hub через локальный сокет `/tmp/Unity-hubIPCService.sock`. Лаунчер отвечает на эти вопросы сам: при открытии проекта запускается фоновая служба `hub_ipc.py`, которая берёт пользователя, токен и организации из сессии Unity CLI и отдаёт их редактору так же, как Hub. Устанавливать Hub не нужно; если он всё-таки запущен, лаунчер оставляет ответы ему. Служба продлевает токен перед истечением, работает и после закрытия лаунчера, пока открыт редактор, и завершается сама через 10 минут после закрытия последнего. Сокет доступен только вашему пользователю. Журнал: `~/.cache/equestria-unity/hub-ipc.log`; журнал самого лаунчера — `~/.cache/equestria-unity/launcher.log`.

**Настройки.** Кнопка «Настройки» вверху открывает окно как в Unity Hub: слева разделы (Лицензии, Проекты, Установки, Шаблоны, Внешний вид, Уведомления, Конфиденциальность, Дополнительно, О программе), справа группы настроек с пояснениями. Папки поиска проектов, расположение установок и шаблонов меняются прямо там.

**Загрузки и баннеры.** В «Настройки → Установки» можно выбрать папку загрузок и число повторов при сбое. Документация Unity CLI не описывает ни параметр папки загрузок, ни число одновременных загрузок, поэтому лаунчер передаёт CLI папку как временную (`TMPDIR`) и число повторов через `UNITY_INSTALL_RETRIES`. Баннеры вверху окна показывают реальные проблемы: нет Unity CLI, нет папок с проектами, не установлены нужные проектам версии редактора. Каждый баннер закрывается, закрытые возвращаются в «Настройки → Уведомления».

**Хранение настроек.** Все настройки описаны в одном месте, `store.py`: тип, значение по умолчанию и допустимые значения каждой. Остальной код читает и пишет их только через него. Неверное значение в файле настроек заменяется значением по умолчанию, а не ломает лаунчер. После любого изменения файл сохраняется, и все окна (проекты, установки, настройки, баннеры, трей) обновляются сами.

## Редакторы и CLI

Версию проекта лаунчер читает из `ProjectSettings/ProjectVersion.txt`, бинарник ищет в каталогах установки. Свою сборку редактора можно указать вручную.

Для каталога релизов, загрузок, модулей, Unity ID, Git, облачных операций и пакетов используется официальный Unity CLI 1.0 (`unity` из PATH или `~/.local/bin`). На вкладке «Редакторы» мастер установки показывает план загрузки перед её началом; там же можно найти обновления патча и добавить модули. Путь установки меняется в «Настройки → Установки». Вкладка «Пакеты» показывает пакеты выбранного проекта прямо из `Packages/manifest.json` и `packages-lock.json`: название, ID, версию и источник, без открытого редактора (флажок «Показывать зависимости» добавляет косвенные). Режим «Unity Registry» показывает пакеты, которые Unity предлагает для версии редактора проекта, с рекомендуемыми версиями (список берётся из файлов установленного редактора, без сети). «Добавить в проект» записывает пакет в `manifest.json`: Unity установит его при открытии проекта или сразу, если редактор открыт. Произвольный ID, Git URL или путь `file:` добавляется через CLI — для этого нужен открытый редактор с Unity Pipeline. Импорт `.unitypackage` требует закрытого проекта. Ход операций виден в «Журнале» (кнопка внизу слева, открывается сам при запуске операции).

Запуск из исходников: `./start.sh`. Установленный пакет даёт команду `equestria-unity` и ярлык меню. Сборка пакета: `makepkg`.

## Темы и запуск под Wayland

В настройках можно выбрать тему персонажа или импортировать собственную палитру JSON. Пример:

```json
{"name": "Twilight", "colors": {"base": "#211a31", "accent": "#dcaafa", "text": "#f2eafa"}}
```

В меню «Редакторы → Управление» у каждой установки есть свой переключатель X11/XWayland и свои аргументы. Прежний включённый общий переключатель переносится на обнаруженные при обновлении установки. Новые движки по умолчанию наследуют окружение сеанса. Профиль X11 передаёт дочернему редактору `GDK_BACKEND=x11`, убирает `WAYLAND_DISPLAY` и требует доступный `DISPLAY`. Редактор конкретной версии может уже использовать XWayland в обоих режимах. Глобальные аргументы задаются в «Настройках», локальные для конкретного проекта — в его меню «⋯». При прямом запуске списки аргументов передаются последовательно: общие, редактора, проекта. Расширения для Inspector в проект не добавляются.

Для проверки закройте редактор, откройте тот же проект обычным профилем и проверьте пипетку и присваивание ссылки. Повторите с профилем X11, сохранив тот же графический API. Проверьте значение поля после снятия подсветки. Из настроек можно открыть Equestria Color Picker, скопировать HEX и вставить в поле цвета Unity. Для ссылки в Inspector доступен выбор объекта через кружок рядом с полем. На Wayland результат захвата за пределами окна зависит от композитора и портала.

## Каталоги Unity

«Редакторы → Установить редактор» открывает официальный каталог для Linux. На первых двух вкладках показаны актуальные выпуски веток и предварительные сборки. В архиве можно выбрать семейство, канал и префикс версии, читать примечания к выпуску и загружать следующие страницы. «Выбрать» (или точный номер в поле «Другая версия») ведёт ко второму шагу — дереву компонентов версии, включая инструменты платформ. На третьем шаге лаунчер запрашивает план загрузки у Unity CLI и показывает версию, модули и объём; установка начинается только кнопкой «Установить». Журнал открывается автоматически, панель операций показывает прогресс и позволяет отменить установку. Процент отображается, когда CLI сообщает его.

«Шаблоны» и «Создать проект» показывают каталог для выбранного редактора. Фильтры «Примеры проектов» и «Учебные проекты» выбирают соответствующие категории Unity. Стрелка ↓ означает, что шаблон будет загружен при создании проекта. Локальные архивы открываются напрямую, для сетевых шаблонов используется Unity CLI.

## Git, GitHub и GitLab

В таблице проектов столбец «Git» показывает ветку и значки состояния: ●3 — изменено файлов, ↑2 — коммитов ещё не отправлено, ↓1 — на сервере есть новые (по последней проверке). Лаунчер читает это из `.git` и `git status`, в том числе когда проект лежит в подпапке репозитория.

Клик по ячейке (или «⋯ → Git…») открывает панель Git проекта: переключение и создание ветки, сводка простыми словами, «Получить изменения» (только fast-forward, ничего не теряется), «Отправить на сервер» (новая ветка создаётся на сервере), список изменённых файлов с галочками и «Сохранить коммит». Каждый шаг идёт как операция лаунчера — виден в верхней строке и в журнале. Ошибки Git объясняются: нет имени и почты для коммитов, не удалось войти на сервер, нет сети, на сервере есть более новые коммиты и т. д. Слияние: «Влить ветку…» и, когда и у вас, и на сервере есть новые коммиты, «Объединить с сервером». Оба начинаются только без несохранённых изменений и после подтверждения. Если слияние остановилось на конфликтах, панель показывает их списком: для каждого файла — «Оставить мою версию», «Взять их версию», «Открыть файл» или «Отметить решённым» (с предупреждением, если в файле остались метки `<<<<<<<`); затем «Завершить слияние» или «Отменить слияние» (возвращает всё как было). Сцены, префабы и другие YAML-ассеты Unity сначала автоматически пробует объединить UnityYAMLMerge из установленного редактора — по свойствам объектов, а не по строкам; файл меняется только если инструмент справился полностью. Пока слияние не завершено, обычный коммит, переключение веток и отправка недоступны. Остальное (история, rebase, cherry-pick) — «Открыть в Git-клиенте»: OpenSourceTree (с версии 1.2.29 открывается сразу на этом репозитории), gitg, Git Cola, GitHub Desktop или GitKraken. Для проекта вне Git — «Инициализировать репозиторий».

В «Проекты → Добавить» клонируйте репозиторий по HTTPS, SSH или локальному пути, либо выберите его из своего аккаунта GitHub (`gh`) или GitLab (`glab`). Войдите через `gh auth login` или `glab auth login`; для обычного Git по HTTPS используйте менеджер учётных данных, для SSH — ключи.

## Без сети и без входа

Проекты, установленные редакторы и запуск редактора не зависят ни от сети, ни от Unity ID. Всё, что обращается к Unity CLI или серверам Unity, идёт в фоне и с ограничением по времени: если сервис Unity не отвечает, операция останавливается и объясняется (30 с для проверки входа и лицензий, 90 с для каталогов и плана загрузки). Установка, загрузка и вход ограничений не имеют, их можно отменить в верхней строке. Ошибки CLI переведены: «нет связи с серверами Unity», «служба лицензий недоступна», «CLI не ответил». Отсутствие входа — обычное состояние, а не ошибка. Unity CLI сам не обновляется (его `update-check` только сообщает о новой версии); лаунчер скачивает CLI только по кнопке.

## Предупреждения Unity о версиях

Unity помечает отдельные версии редактора так же, как Hub: «Уязвимость» (собранные этой версией приложения уязвимы, обновите перед публикацией) или «Предупреждение» (известная ошибка). Лаунчер берёт эти отметки из официального каталога релизов и показывает их на карточках редакторов и в мастере установки; по клику открывается бюллетень Unity. Если уязвимость есть у установленного редактора, вверху окна появляется баннер.
