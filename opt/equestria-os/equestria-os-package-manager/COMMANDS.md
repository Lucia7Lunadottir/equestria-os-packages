# equestria-os-package-manager — команды и действия GUI

Один процесс на PyQt6. Привилегии (`pkexec`) запрашиваются точечно — только под конкретную команду удаления, не под всё приложение.

## Откуда берётся список пакетов (`refresh_packages()`, `main.py:479`)

| Источник | Команда листинга | Объяснение |
|---|---|---|
| pacman (нативные) | `pacman -Qnq` | `-Q` — режим запроса к локальной базе установленных пакетов (не к репозиториям в сети). `-n` — только «native», то есть пакеты именно из официальных репозиториев Arch, исключая AUR/сторонние. `-q` — «тихий» вывод, только имена пакетов без версий — удобно парсить построчно. |
| детали пакета | `pacman -Qi` (`_enrich_pacman()`, `main.py:542`) | `-i` — подробная информация (описание, размер, зависимости) вместо просто имени. |
| AUR (yay) | `yay -Qmq` | `-m` у pacman/yay значит «foreign» — пакеты, установленные не из официальных репозиториев (то есть AUR, раз yay сам собирает именно оттуда). |
| Flatpak | `flatpak list --app ...` | `--app` исключает из списка runtime-пакеты (общие библиотеки для приложений) — только сами программы, которые пользователь мог бы захотеть удалить. |
| Snap | `snap list` | Стандартный листинг snapd. |
| pip (пользовательские) | `pip list --user --format=freeze` | `--user` — только пакеты, установленные в домашний каталог пользователя (`pip install --user`), не системные (те трогать через pip опасно — конфликтуют с pacman). `--format=freeze` — вывод вида `name==version`, как в `requirements.txt`, легко парсить. |
| владелец файла | `pacman -Qo <files>` (`_enrich_pacman()`) | `-o` — «owns»: по пути к файлу узнать, каким пакетом он был установлен. |

Ни поиск, ни листинг не требуют root — все привилегированные действия только на удалении.

## Удаление пакета (`execute_uninstall()`, `main.py:702-758`) — команда зависит от источника

| Источник | Команда | Объяснение флагов |
|---|---|---|
| **pacman/AUR** (всё, что не перечислено ниже) | `pkexec pacman -Rns --noconfirm <pkg>` | `-R` — remove. `-n` — не сохранять конфигурационные файлы пакета (`.pacsave`), которые pacman иначе оставляет на диске «на всякий случай». `-s` — recursive: заодно удалить зависимости, которые ставились только ради этого пакета и больше никем не используются (buquette-эффект «осиротевших» пакетов иначе накапливается годами). `--noconfirm` — не задавать интерактивных вопросов (нужно для запуска не из интерактивного терминала). |
| **flatpak** | `flatpak uninstall -y [--delete-data] <app_id>` | `-y` — автоподтверждение. `--delete-data` заставляет flatpak самостоятельно почистить и `~/.var/app/<app_id>` (там приложение хранит свои настройки/данные) — GUI сам этот путь не трогает именно поэтому. |
| **snap** | `pkexec snap remove [--purge] <pkg>` | `--purge` — удалить вместе со всеми ревизиями и пользовательскими данными snap-пакета, а не оставлять их на случай отката к прошлой версии (стандартное поведение snap без флага). |
| **pip** | `pip uninstall -y <pkg>` — **без** `pkexec` | Пользовательские pip-пакеты лежат в `~/.local`, там не нужны права root; `-y` — не спрашивать подтверждения. |
| **curl** (вручную установленное) | `official_cmd` из `CURL_INSTALLS`, либо `rm -rf <remove_paths>` | Если у приложения есть свой штатный анинсталлятор (`official_bin` существует) — используется он; иначе — прямое удаление известных путей установки. |

Все команды идут через `subprocess.run(["/bin/bash", "-c", cmd])` — сначала команда строится строкой с `shlex.quote()` на всех пользовательских значениях (экранирование, чтобы имя пакета со спецсимволом не сломало команду и не позволило подставить постороннюю), затем целиком передаётся в `bash -c`.

## «Удалить также данные приложения» (чекбокс в диалоге подтверждения)

* **`leftover_candidates()`** (`main.py:335-371`) ищет по **точному** совпадению имени (без регистра, без догадок) в: `~/.config`, `~/.cache`, `~/.local/share`, `~/.local/state`, плюс `~/.cache/yay` для AUR-пакетов, плюс скрытая папка `~/.<имя>`. Для flatpak/snap — сразу конкретный путь (`~/.var/app/<app_id>` / `~/snap/<pkg>` — это фиксированные, документированные Flatpak/Snap места хранения данных приложения, не предположение).
* Если пользователь поставил галочку — после успешного удаления пакета каждый найденный путь чистится через `shutil.rmtree()` (папки) или `os.remove()` (файлы) — обе функции стандартной библиотеки Python, не внешние команды; `pkexec` тут не нужен — все эти пути и так в домашнем каталоге пользователя.

## После удаления curl-приложения — уведомление про rc-файлы

* **`scan_rc_lines()`** (`main.py:780-798`) реально читает `~/.bashrc`, `~/.zshrc` и т.п. (`RC_FILES`) и ищет строки, совпадающие с `RC_LINE_PATTERNS` для конкретной curl-записи (например, строку, добавляющую каталог в `PATH`) — показывает только то, что реально нашло в файле, не шаблон «обычно там бывает такое».
* **`remove_rc_lines()`** (`main.py:801-816`) — если пользователь подтвердит в уведомлении, вычищает найденные строки из этих файлов.

## Прочее

* PIP-конфликт (`scan_pip_conflict()`, `main.py:679-698`) — перед удалением системного пакета проверяет через `pip list --user --format=freeze`, не установлен ли одноимённый pip-пакет, который может перекрывать системный в `PATH`/`site-packages`, и требует явного подтверждения через отдельный чекбокс.
* Ничего из вышеперечисленного не запускается автоматически/по расписанию — только по явному клику «Удалить» в диалоге подтверждения.
