# desktop-editor-ui — команды и действия GUI

Однофайловое PyQt6-приложение (`desktop_editor_ui.py`), без прав root, без бэкенда — вся логика в одном процессе.

## Поля формы → итоговый `.desktop`-файл

`generate_desktop_content()` (`desktop_editor_ui.py:327-362`) собирает файл в таком порядке:

```ini
[Desktop Entry]
Type=Application
Name=<Имя приложения>
Comment=<Описание>            # если заполнено
Name[<lang>]=...              # по одной строке на каждую добавленную локализацию
Comment[<lang>]=...
Exec=<Пре-аргументы> "<Путь к файлу>" <Пост-аргументы>
Icon=<Иконка>                  # если заполнено
Categories=<Категория>;
Terminal=false
```

> **Формат `.desktop`** — это не изобретение проекта, а стандарт freedesktop.org (Desktop Entry Specification), который понимают KDE, GNOME и вообще все Linux-DE. `Type=Application` говорит менеджеру приложений «это запускаемая программа, а не ссылка/директория». `Terminal=false` — запускать без открытия окна терминала. `Categories=Utility;` — определяет, в каком разделе меню «Пуск» окажется ярлык (значения категорий тоже стандартизированы спецификацией, не проектные).

* **«Пре-аргументы»** (`pre_args_input`, строка 171) — подставляются ПЕРЕД путём в `Exec=`, для интерпретаторов вроде `python3` или `wine`. Без них `Exec=/путь/script.py` система попытается исполнить файл напрямую, что не сработает без shebang с правами на выполнение.
* **Путь к файлу / «Обзор»** (`browse_exec()`, `desktop_editor_ui.py:286-289`, через `QFileDialog.getOpenFileName`) — сам путь оборачивается в двойные кавычки (строка 341: `exec_path = f'"{exec_path}"'`), чтобы пробелы в пути не разбили `Exec=` на несколько аргументов при разборе файла средой рабочего стола.
* **«Пост-аргументы»** — подставляются ПОСЛЕ пути, например `--fullscreen`.
* **Иконка / «Выбрать»** (`browse_icon()`, `desktop_editor_ui.py:291-294`) — принимает либо абсолютный путь к файлу (`.png`/`.svg`/`.xpm`), либо имя иконки из текущей темы (`QIcon.fromTheme`, строка 308) — это тот же механизм, которым сама KDE ищет иконки по имени вроде `firefox` без указания полного пути; превью обновляется на лету в `update_icon_preview()` (строка 296).
* **«Добавить перевод»** (`add_localization()`, строка 319) — открывает `LocalizationDialog`, добавляет пару `Name[xx]`/`Comment[xx]` — тоже часть спецификации: у `.desktop`-файла может быть локализованное имя на каждый язык интерфейса, среда сама выбирает нужный по текущей локали пользователя.

## Кнопки действий

| Кнопка | Метод (`desktop_editor_ui.py`) | Что реально происходит |
|---|---|---|
| **Установить в меню Пуск** | `install_to_menu()`, строки 364-377 | Пишет файл в `~/.local/share/applications/<имя>.desktop` (создаёт каталог при необходимости), `os.chmod(path, 0o755)` — делает файл исполняемым (без этого бита некоторые файловые менеджеры/DE отказываются запускать `.desktop` из недоверенного места), затем `os.system("update-desktop-database <каталог>")`. |
| **Сохранить как...** | `save_as()`, строки 379-389 | `QFileDialog.getSaveFileName` → пишет файл туда, куда указал пользователь, добавляя `.desktop`, если расширения нет; тот же `chmod 755`. |
| **Очистить форму** | `clear_form()`, строки 391-400 | Просто сбрасывает все поля формы, ничего не пишет на диск. |

> **`update-desktop-database`** — утилита пакета `desktop-file-utils`. Она не создаёт и не проверяет отдельные `.desktop`-файлы — она перестраивает бинарный кэш-индекс `mimeinfo.cache` в каталоге приложений (какие MIME-типы какими программами открывать). Без этого шага KDE/GNOME могут не сразу «увидеть» новый ярлык в меню или в диалоге «Открыть с помощью» — кэш обновляется по требованию, а не при каждом изменении файла. `>/dev/null 2>&1` в конце — команда без диагностики, отсутствие утилиты просто ничего не сломает и не покажет пользователю технический вывод.

## Прочее

* root/pkexec не используется нигде — файл всегда пишется в домашний каталог текущего пользователя, там достаточно обычных прав.
* Переводы UI грузятся из любых `*.json` в каталоге приложения (`load_translations()`, строки 71-85); если файлов нет — используется зашитый в код словарь `ru`/`en` (строки 88-114).
