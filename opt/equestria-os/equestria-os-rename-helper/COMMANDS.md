# equestria-os-rename-helper — команды и действия GUI

Никаких внешних команд и `pkexec` — всё делается прямо в GUI-процессе через `os.rename()` (системный вызов, который атомарно переименовывает файл — либо целиком срабатывает, либо целиком не срабатывает, промежуточного состояния «наполовину переименовано» быть не может). Права root никогда не запрашиваются.

## Формирование нового имени (`_get_new_name()`, `rename_app.py:237-254`)

Применяется в таком порядке к каждому файлу (расширение не трогается, отделяется через `os.path.splitext` — стандартная функция Python, разбивающая `"file.tar.gz"` на `("file.tar", ".gz")` по последней точке):
1. **Find/Replace** — `name.replace(find_txt, replace_txt)` — простая подстрока-в-подстроку замена (не regex), только если поле «найти» не пустое.
2. **Префикс/суффикс** — `f"{prefix}{name}{suffix}"`.
3. **Нумерация** — если выставлено стартовое число > 0, дописывается `_NNN` (3 цифры с ведущими нулями через формат `:03d`, `start_num + index`), где `index` — порядковый номер файла в списке (после фильтра).

## Кнопки

| Действие | Метод (`rename_app.py`) | Что происходит |
|---|---|---|
| «Выбрать папку» | `_select_dir()`, строка 231 | `QFileDialog.getExistingDirectory` (системный диалог выбора папки), сразу обновляет предпросмотр. |
| Любое изменение полей формы | `_update_preview()`, строки 256-294 | `os.listdir(dir)` (без рекурсии — только файлы верхнего уровня, отфильтрованные через `os.path.isfile`), применяет фильтр по подстроке, показывает список `старое → новое`; конфликтующие переименования (два файла → одно имя, или имя уже занято) подсвечиваются красным с пометкой «⚠ конфликт!». |
| «Переименовать» | `_do_rename()`, строки 296-330 | Проверяет отсутствие конфликтов (дубли в новых именах / занятые чужие имена) **до** первого `os.rename()`; переименовывает файлы по одному в цикле, каждый успех добавляется в `rename_history` для отмены; при ошибке на отдельном файле (`OSError`/`PermissionError`, пойманные как общий `Exception`) — предупреждение, но остальные файлы всё равно обрабатываются. |
| «Отменить» | `_do_undo()` → `_apply_undo_batch()`, строки 332-365 | Проходит по последнему батчу истории в обратном порядке: `os.rename(new_path, old_path)` — та же атомарная операция, но в обратную сторону. Если файл с новым именем не найден или старое имя уже кем-то занято — пропускает с сообщением об ошибке, не прерывая остальные. |
| «История» | `_show_history()` | Диалог со списком прошлых батчей переименования; выбор конкретного батча вызывает тот же `_apply_undo_batch()` для отмены именно его (не обязательно последнего). |

## ⚠ Важная находка: не рассчитывайте на повышение прав здесь

Файл импортирует `privilege.py` (`import privilege`, `rename_app.py:14`), но **ни разу не вызывает** ни одну его функцию — это мёртвый импорт, судя по всему скопированный из `equestria-os-relocator` при создании проекта и не убранный. Более того, в самом `privilege.py` путь к бэкенду (`BACKEND = ".../disk_backend.py"`) указывает на файл, которого в этом пакете вообще не существует — если бы код и вызывался, он бы упал с `FileNotFoundError`. То же самое верно для `core.py` (там лежит функция `relocate()` для переноса файлов с симлинком, скопированная из того же relocator — тоже не используется, не про переименование).

**Практический вывод:** если папка/файлы недоступны на запись текущему пользователю (например, что-то в `/opt` или в чужом домашнем каталоге), `os.rename()` просто выбросит исключение `PermissionError`, будет показано окно с ошибкой по каждому такому файлу — никакого запроса пароля не будет, потому что механизм повышения прав в этом приложении физически не подключён к рабочему коду.
