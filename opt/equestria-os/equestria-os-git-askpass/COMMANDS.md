# equestria-os-git-askpass — команды и действия GUI

Нет постоянно запущенного окна — это **askpass-хелпер**: механизм, изначально придуманный для SSH ещё в 1990-х (переменная `SSH_ASKPASS`), который Git позже перенял для себя (`core.askPass`). Идея одна и та же: вместо того чтобы просить пароль прямо в терминале (что не работает, если программу запустили из GUI без терминала вообще), Git/SSH ищут отдельную программу-«спрашивателя» и запускают её `<askpass-программа> "<текст запроса>"`, ожидая пароль в её stdout.

## Как это подключается к системе (делает `.install`-скрипт пакета — `equestria-os-git-askpass.install`, не сам GUI)

| Событие пакета | Команда | Объяснение |
|---|---|---|
| `post_install` / `post_upgrade` | `git config --system core.askPass /usr/bin/equestria-os-git-askpass` | `git config --system` пишет в `/etc/gitconfig` (общий для всех пользователей системы, в отличие от `--global` — только для текущего, или `--local` — только для одного репозитория). `core.askPass` — стандартная переменная конфигурации Git, которую сам Git проверяет каждый раз, когда HTTPS-репозиторий просит логин/пароль. |
| `post_install` / `post_upgrade` | Прописывает `SSH_ASKPASS=/usr/bin/equestria-os-git-askpass` в `/etc/environment` (через `_set_env_var()` — заменяет строку `sed`-ом, если уже есть, иначе дописывает) | `/etc/environment` — системный файл, который `pam_env` читает при **каждом входе в систему** и раскладывает как переменные окружения по всем сессиям пользователя (это не то же самое, что `~/.bashrc` — работает даже для программ, запущенных не из терминала). `SSH_ASKPASS` — переменная, которую проверяет `ssh`/`ssh-add`, если у него нет доступа к терминалу для ввода passphrase (например, ssh вызван из графической программы). Также `/etc/profile.d/equestria-os-git-askpass.sh` экспортирует ту же переменную для login-шеллов (шеллов, запущенных как «сессия входа», а не как дочерний процесс уже открытого терминала) — второй, более узкий путь той же настройки на случай, если `/etc/environment` почему-то не подхватился. |
| `pre_remove` | `git config --system --unset core.askPass`; убирает строку `SSH_ASKPASS=` из `/etc/environment` | Аккуратный откат при удалении пакета — не оставляет систему ссылающейся на удалённый бинарь. |

**Важно:** SSH-часть требует перелогина — `SSH_ASKPASS` читается из `/etc/environment` только при старте новой сессии входа (это работа `pam_env`, а не что-то, что можно «применить сейчас» без выхода из системы), об этом сам post_install и печатает предупреждение.

## Сам GUI (`equestria-os-git-askpass.py`)

* `main()` (строка 107) берёт текст запроса из `sys.argv[1]` — его передаёт сам Git/SSH при вызове, например `Password for 'https://...':` или `Enter passphrase for key ...`. Программа не решает сама, когда её вызывать — это делает Git/SSH по своей внутренней логике аутентификации.
* Если в тексте запроса встречается одно из слов `password`, `token`, `passphrase`, `secret`, `пароль` (`_secret_keywords`, строка 62) — поле ввода становится скрытым (`QLineEdit.EchoMode.Password`, строка 68) и появляется кнопка-глазок для показа/скрытия. Иначе поле обычное (например, для логина/username — Git тоже иногда спрашивает его отдельным вызовом askpass).
* **OK** → печатает введённое значение в stdout (`get_value()`, строка 104), `exit(0)` — это то, что Git/SSH получают как ответ на свой запрос через обычный межпроцессный канал (stdout дочернего процесса).
* **Отмена** → `exit(1)`, ничего не печатается — операция Git/SSH завершится ошибкой аутентификации, как будто пользователь ввёл неверный пароль трижды.

## Прочее

* Никаких файлов, кроме своих собственных настроек, приложение не пишет — оно ничего не сохраняет и не кеширует само. Если пароль запоминается между запусками — это делает `git credential-cache`/`ssh-agent` независимо от этого askpass-хелпера, который лишь один раз передаёт введённое значение и завершается.
* Иконка ищется по фиксированному пути `/usr/share/pixmaps/equestria-os-git-askpass.png` (устанавливается PKGBUILD'ом), при отсутствии — иконка темы `preferences-desktop-theme` (`QIcon.fromTheme` — стандартный механизм Qt/freedesktop искать иконку по общепринятому имени в текущей иконочной теме, без указания точного файла).
* Локализация — `localization.csv` рядом со скриптом, язык определяется из переменной окружения `$LANG`.
