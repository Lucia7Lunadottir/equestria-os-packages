# equestria-os-software-center — команды и действия GUI

## Откуда берётся список программ (`workers.py`)

| Источник | Механизм | Объяснение |
|---|---|---|
| Официальные репозитории Arch | `pacman -Sl` (базовый список) + `expac` (если установлен) | `-S` + `-l` (list) у pacman выводит все пакеты во всех подключённых репозиториях (не только установленные — `-Q` был бы для этого). `expac` — сторонняя утилита, которая умеет вытаскивать поля метаданных пакета в произвольном формате гораздо быстрее, чем по одному вызывать `pacman -Si` на каждый пакет. |
| AUR | HTTP-запрос к `https://aur.archlinux.org/rpc/v5/search/<query>` и `/rpc/v5/info?arg[]=...` | Это официальный RPC (Remote Procedure Call) API самого AUR — тот же протокол, которым пользуются `yay`/`paru` для поиска, но здесь вызывается напрямую по сети, без установленного AUR-помощника. |
| Flatpak | Метаданные — из AppStream/metainfo (`/usr/share/metainfo`, `/usr/share/appdata`) | AppStream — открытый XML-формат метаданных приложений (описание, скриншоты, категории), который сами пакеты кладут на диск при установке — общий стандарт, не специфичный для Flatpak. |
| Обновления AUR | `yay -Qu --aur` (`AURUpgradableLoader`, `workers.py:328-351`) | `-Qu` — «query, upgradable»: список установленных пакетов, у которых есть более новая версия; `--aur` ограничивает проверку только AUR-пакетами (без нужды дважды опрашивать официальные репозитории — ими уже занимается `pacman -Qu`). |
| Описание пакета по требованию | `pacman -Si <pkg>` (`PacmanInfoLoader`, `workers.py:354-380`) | `-Si` — информация о пакете из синхронизированной базы репозитория (не из уже установленных, в отличие от `-Qi`), используется, когда `expac` не установлен и нужно подтянуть описание в момент открытия карточки. |

Ни поиск, ни листинг не требуют root — все привилегированные действия только на установке/удалении/изменении конфигурации.

## Установка / удаление (`install_package()`/`remove_package()`, `main.py:1134-1154`)

| Источник | Установить | Удалить |
|---|---|---|
| pacman (новый пакет) | `pkexec pacman -S --noconfirm <pkg>` | `pkexec pacman -Rs --noconfirm <pkg>` |
| pacman (есть обновление) | `pkexec pacman -Syu --noconfirm <pkg>` | — |
| AUR | `yay -S --noconfirm <pkg>` (без `pkexec`) | — |
| Flatpak (новое) | `flatpak install -y flathub <app_id>` | `flatpak uninstall -y <app_id>` |
| Flatpak (обновление) | `flatpak update -y <app_id>` | — |

`-Rs` — remove с автоматическим удалением зависимостей, которые ставились только ради удаляемого пакета и больше никем не используются (то же `-s`, что и в package-manager). `yay` без `pkexec` — сам вызывает повышение прав внутри себя для pacman-части транзакции, но интерактивно спрашивает про AUR-специфичные шаги (просмотр PKGBUILD, разрешение на сборку) — поэтому и запускается в видимом терминале, а не тихо через `pkexec`.

Все команды открываются в **`konsole -e bash -c "<cmd>"`** — прогресс виден пользователю живьём, не скрыт за прогресс-баром.

**«Установить выбранное»** (`install_selected_essentials()`/`_on_essentials_classified()`, `main.py:1156-1199`) — сначала классифицирует все выбранные имена пакетов фоновым потоком (`pacman -Si <name>` на каждое: успех → «официальный», неуспех → «AUR»), затем **двумя отдельными шагами** в одном окне консоли — сначала `pkexec pacman -S --noconfirm <официальные через пробел>`, потом `yay -S --noconfirm <AUR через пробел>`. Разделены специально: если смешать в одной команде pacman, вся транзакция целиком оборвётся на первом же незнакомом (AUR) имени — pacman не умеет частично выполнить список пакетов, если хоть одно имя ему неизвестно.

## Обновление системы (кнопка «Обновить всё»)

Тот же самоисцеляющийся скрипт, что в Settings → Обновления: `pkexec pacman -Syu --noconfirm` → при ошибке о медленных/недоступных зеркалах — переранжирование через `pkexec pg-rankmirrors-backend rank <страна по ipinfo.io>` (см. `pg-rankmirrors/COMMANDS.md`) и повтор → при конфликте пакетов — автоматический `pkexec pacman -Rdd --noconfirm <конфликтующие>` и повтор → затем `yay -S --noconfirm <pkg>` по одному для всех AUR-обновлений → `flatpak update -y`, если установлен. (Дословно та же логика, что в `equestria-os-settings/modules/mod_auto_update.py` — если чинишь одно, проверь и второе место.)

## Очистка кеша пакетов (`execute_cache_clean()`, `main.py:1272-1337`, диалог с выбором «обычная»/«полная»)

| Шаг | Обычная (`main.py:1309`) | Полная (`main.py:1299`) |
|---|---|---|
| Pacman | `paccache -rvk2 && paccache -rvuk0` | `paccache -rvk0` |
| Если `paccache` не установлен | `pacman -Sc --noconfirm` | `find /var/cache/pacman/pkg -maxdepth 1 -name '*.pkg.tar*' -delete` |

> **`paccache`** — отдельная утилита из `pacman-contrib`, специализированная на чистке `/var/cache/pacman/pkg` (папки, куда pacman складывает СКАЧАННЫЕ пакеты — не удаляет их автоматически после установки, на случай отката). `-r` — удалить (remove), `-v` — подробный вывод. `-k2` — «keep 2»: оставить по 2 последних версии каждого пакета в кеше (позволяет откатиться на одну версию назад при необходимости). `-k0` — оставить 0, то есть удалить вообще все закешированные версии, включая текущую установленную. `-u` в `-rvuk0` — «uninstalled»: относится только к пакетам, которых уже нет в системе (были удалены, а их старые версии в кеше остались занимать место) — сочетание `paccache -rvk2` (для установленных, оставить 2) + `paccache -rvuk0` (для удалённых пакетов, не оставлять вообще) даёт «обычную» уборку без потери возможности отката недавно установленного.
>
> Если `paccache` нет вообще — `pacman -Sc` (sync clean) сам умеет чистить кеш, но интерактивно спрашивает подтверждение по умолчанию отвечая «нет», поэтому код добавляет `--noconfirm`, чтобы получить положительный ответ автоматически.
>
> Оба варианта сначала выполняют `pkexec bash -c 'rm -rf /var/cache/pacman/pkg/download-*'` — это недокачанные файлы (pacman называет их `download-*` во время скачивания, переименовывая в финальное имя только по завершении) — их можно смело удалять в любой момент, они не являются рабочими пакетами.

Дальше в том же скрипте: `yay -Sc --noconfirm` (у `yay` своя команда очистки кеша, включающая AUR-сборочный кеш) + `rm -rf ~/.cache/yay/` (папка, где yay хранит склонированные git-репозитории PKGBUILD'ов AUR-пакетов между сборками — без `pkexec`, это в домашнем каталоге), и `flatpak uninstall --unused -y` (`--unused` — удалить runtime-пакеты, на которые больше не ссылается ни одно установленное Flatpak-приложение, безопасная автоматическая уборка).

## Добавление стороннего репозитория pacman (`pacman_repo.py`)

Полноценный парсер/сериализатор `/etc/pacman.conf` с реальными гарантиями безопасности:
1. Собранный новый текст файла **сначала проверяется** через `pacman-conf --config <временная_копия> --repo-list` (`_validate_with_pacman_conf()`, `pacman_repo.py:244-271`) — `pacman-conf` это официальная утилита, которая делает то же самое, что и сам pacman при чтении конфига, но только выводит результат разбора, ничего не устанавливая; если она сама отказывается его парсить — файл **не трогается вообще**, root не запрашивается.
2. Если проверка прошла — `PrivilegedWriter.write()` (`pacman_repo.py:274-303`) пишет содержимое во временный файл, затем одним вызовом `pkexec sh -c 'install -m 644 -o root -g root -T "$1" "$2" && mv -f "$2" "$3"' _ <tmp> <path>.new <path>` копирует и переименовывает поверх настоящего `/etc/pacman.conf`. `install` (не путать с `pacman -S`/установкой пакетов — это отдельная древняя Unix-утилита копирования файлов с заданием прав/владельца одной командой) с `-m 644 -o root -g root` ставит права и владельца сразу при копировании. `-T` — трактовать второй аргумент как конкретное имя файла, а не как папку назначения (защита от неожиданного поведения `install`, если целевой путь вдруг окажется директорией). Финальный `mv -f` — **атомарная** операция в пределах одной файловой системы: с точки зрения любого другого процесса файл либо старый, либо уже новый целиком, никогда не «наполовину записанный» — обрыв polkit-авторизации или ошибка копирования никогда не оставляет `/etc/pacman.conf` в повреждённом состоянии.

## Настройки (`settings.py`)

Чисто локальный JSON в `~/.config/equestria-os-software-center/settings.json`, без команд: язык интерфейса, какие источники включать при обновлении (`update_pacman`/`update_aur`/`update_flatpak`) и показывать ли вообще AUR/Flatpak как источники (`enable_aur`/`enable_flatpak`) — именно эта настройка отключает AUR «в сторе», если галочка снята, а не удаление какого-то кода.

## Прочее

* **«Установить Flatpak»** (если не установлен) → `pkexec pacman -S --noconfirm flatpak`.
* **«Добавить Flathub»** → `pkexec flatpak remote-add --if-not-exists flathub <url Flathub>` — `--if-not-exists` делает команду безопасной для повторного запуска (не выдаст ошибку, если Flathub уже подключён).
