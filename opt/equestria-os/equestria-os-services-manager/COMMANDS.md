# equestria-os-services-manager — команды и действия GUI

Простая обёртка над `systemctl` — вся логика в одном `main.py`, нет отдельного бэкенд-процесса.

> **systemd/systemctl вкратце** — systemd это init-система (первый процесс, который запускает Linux после ядра, и менеджер всего остального: служб, точек монтирования, таймеров). «Сервис» (`.service`-юнит) — описание одной фоновой программы: как её запускать, от чьего имени, когда автоматически стартовать. «Активен» (`active`) — служба сейчас реально запущена. «Включена» (`enabled`) — служба настроена стартовать автоматически при загрузке системы; это НЕ то же самое, что «активна» — можно выключить уже работающую службу без изменения автозапуска, и наоборот, включить автозапуск не запуская её прямо сейчас.

## Получение списка сервисов (`_fetch_scope()`, `main.py:36-91`; `_refresh_single()`, `main.py:100-...`)

Для каждого из двух scope — **system** и **user** (флаг `--user`, определяющий, слушает ли `systemctl` системный менеджер systemd (PID 1) или персональный менеджер конкретного пользователя):
* `systemctl [--user] list-unit-files --type=service --no-pager --no-legend` — список юнитов и их enabled/disabled состояние. `--type=service` — только службы, не таймеры/точки монтирования/сокеты (systemd управляет ими всеми похожим образом, но здесь интересны только службы). `--no-pager` — не открывать вывод в постраничном просмотрщике (`less`), который иначе используется по умолчанию и не подходит для программного парсинга. `--no-legend` — не печатать заголовок таблицы и итоговую строку, только сами данные.
* `systemctl [--user] list-units --all --type=service --no-pager --no-legend --full` — активен/неактивен, текущее состояние. `--all` — включая неактивные и невыгруженные (без флага показываются только активные/недавно упомянутые). `--full` — не обрезать длинные имена юнитов многоточием в выводе.

`_refresh_single()` (обновление одной строки после действия) — `systemctl [--user] show <svc> --no-pager ...` — `show` печатает **все** свойства юнита в формате `Ключ=Значение` (аналог `systemctl status`, но машиночитаемо, без форматирования для человека).

## Действия — двойное подтверждение, разные команды для system/user

| Действие | Как определяется (`main.py`) | Команда |
|---|---|---|
| Старт/Стоп (клик по строке) | `_confirm_start_stop()`, строка 379: если сервис `active` → действие `stop`, иначе `start` | `systemctl --user start\|stop <svc>` (сервисы пользователя) или `pkexec systemctl start\|stop <svc>` (системные) |
| Включить/Выключить автозапуск | `_confirm_enable_disable()`, строка 385: если уже `enabled` → действие `disable`, иначе `enable` | То же различие user/system |

Оба действия сначала показывают модальное окно подтверждения с текстом «точно хотите start/stop/enable/disable <сервис>?» — реального вызова `systemctl` без явного клика «ОК» не происходит (`execute_action()`, `main.py:397-414`).

**Разница по правам:** для сервисов уровня **user** — обычный `systemctl --user`, без повышения прав вообще (это сервисы самого пользователя — например, его собственный таймер обновлений — root не нужен, они и так работают под его учётной записью). Для сервисов уровня **system** (например, сетевые службы, влияющие на всю систему) — всегда `pkexec systemctl ...`, то есть системный пароль/подтверждение полкита при каждом действии.

## Прочее

* Никаких файлов конфигурации сам модуль не хранит и не пишет — вся истина берётся напрямую из `systemctl` при каждом обновлении списка (в отличие, например, от `equestria-os-swap-manager`, который пишет свои конфиги в `/etc/sysctl.d/`).
* После успешного действия обновляется только одна строка (`_refresh_service_async()`), не весь список — так что при переключении множества сервисов подряд не будет полного повторного скана всех юнитов системы.
