# equestria-os-character-theme — команды и действия GUI

Один процесс, без pkexec/root — всё пишется в `~/.config`, `~/.local/share`, `~/.bashrc` от имени текущего пользователя. Привилегии не нужны, поэтому если что-то не применяется — дело не в правах.

Пользовательские данные (персонажи, обои, метки) живут в `~/.local/share/EquestriaOS/Themes/` (`USER_PATH`, `main.py:16`), а не рядом с самим приложением — при первом запуске `init_user_folder()` (`main.py:101-121`) копирует туда `characters.json`, `Wallpapers/`, `MLP Cutiemarks/` из системного каталога, но только если у пользователя их ещё нет.

## Инструменты, которыми всё это управляется

> **`qdbus6`** (`find_qdbus()`, `main.py:20-31`) — консольный клиент к шине D-Bus, межпроцессному «телефону» Linux-десктопа. KDE Plasma управляется не через файлы конфигурации напрямую (хотя они и есть), а через D-Bus-объекты, у которых можно вызывать методы прямо из командной строки: `qdbus6 <служба> <путь-объекта> <метод> [аргументы]`. `org.kde.plasmashell /PlasmaShell org.kde.PlasmaShell.evaluateScript "<JS>"` — это буквально «выполни этот JavaScript внутри самого Plasma Shell» — API, которым сама Plasma и её собственные настройки внутренне манипулируют рабочим столом (панелями, виджетами, обоями). Бинарь несколько раз переименовывали в истории KDE (`qdbus` → `qdbus6`), поэтому код перебирает варианты, а не полагается на одно имя.

> **`kwriteconfig6`/`kreadconfig6`** — официальные утилиты KDE для чтения/записи `.ini`-подобных конфигов KDE (`kdeglobals`, файлы цветовых схем и т.п.) по формату `--file <файл> --group <секция> --key <ключ> <значение>`. Они существуют именно потому, что писать эти файлы руками рискованно — KDE следит за форматом (экранирование, порядок групп), а эти тулы гарантируют корректность.

> **`plasma-apply-colorscheme <имя>`** — официальная утилита, которая берёт файл цветовой схемы по имени (из `~/.local/share/color-schemes/` или `/usr/share/color-schemes/`) и применяет её ко всему запущенному KDE разом (панели, приложения, тема окон) — без неё пришлось бы вручную рассылать сигналы всем открытым Qt-приложениям.

## Клик по карточке персонажа → `on_character_selected()` (`main.py:492-501`)

Один клик запускает 5 функций применения темы по очереди:

1. **`apply_wallpaper_slideshow()`** (`main.py:683-689`) — `qdbus … evaluateScript` со скриптом на JS: `desktops()` — встроенная функция Plasma Shell API, которая возвращает список всех рабочих столов; для каждого выставляет `wallpaperPlugin = 'org.kde.slideshow'` и пишет путь к папке в его конфиг (`writeConfig('SlidePaths', ...)`). Отдельно `kwriteconfig6 --file kscreenlockerrc` — то же самое, но для экрана блокировки (это отдельная от рабочего стола Plasma-компонента со своим конфигом).
2. **`apply_kde_theme()`** (`main.py:812-855`) — генерирует цветовую схему KDE `EG_Active_A`/`EG_Active_B` (чередуются между вызовами, чтобы `plasma-apply-colorscheme` гарантированно перечитал файл, даже если формально имя не поменялось — иначе Plasma может решить «схема та же самая, перерисовывать нечего»): копирует существующую схему персонажа (`~/.local/share/color-schemes/` → `/usr/share/color-schemes/` → `Breeze{Dark,Light}` как крайний фолбэк, если ни системной, ни пользовательской версии не нашлось) в `$TARGET_FILE`, накладывает акцентный цвет через `kwriteconfig6`, пишет `AccentColor`/`LastUsedCustomAccentColor` в `kdeglobals` (глобальный конфиг KDE, который читают ВСЕ Qt/KDE-приложения при старте), и вызывает `plasma-apply-colorscheme`. Отдельно `_recolor_panel_sysmon()` (`main.py:857-878`) через `qdbus … evaluateScript` перекрашивает график памяти в виджетах системного монитора на панелях — `panels()`/`widgetById()`/`writeConfig` тут снова методы того же Plasma Shell Scripting API, а не что-то специфичное для этого проекта.
3. **`apply_fastfetch()`** (`main.py:691-737`) — пишет `~/.config/fastfetch/config.jsonc`. `fastfetch` — консольная утилита вывода информации о системе (аналог классического `neofetch`, но быстрее); она сама ничего не запускает, только читает свой JSON-конфиг при следующем запуске. `chafa`/`imagemagick` тут не вызываются напрямую этим приложением — это зависимости самого `fastfetch` для отрисовки иконки как ASCII/block-графики в терминале.
4. **`apply_konsole_colors()`** (`main.py:739-749`) — пишет файл цветовой схемы терминала Konsole (`~/.local/share/konsole/EquestriaOS.colorscheme` — формат `.ini` с RGB по каждому из 16 ANSI-цветов + фон/текст), затем через `qdbus` перебирает все запущенные сессии Konsole (`for s in $(qdbus | grep konsole)`, `for e in $(qdbus $s | grep Sessions)`) и вызывает `org.kde.konsole.Session.setColorScheme` — метод D-Bus API самого Konsole для смены темы уже открытого окна без перезапуска. На новых версиях Konsole этот метод убран из API (остался только `setProfile`) — вызов тихо ничего не делает, а не падает, схема всё равно подхватится при следующем открытии профиля.
5. **`apply_konsole_profile()`** (`main.py:751-806`) — создаёт:
   * `~/.local/share/konsole/eg_character_prompt.sh` — кастомный `PS1` (переменная окружения bash, определяющая вид приглашения командной строки) с именем персонажа;
   * `~/.local/share/konsole/eg_active.bashrc` — сначала грузит обычный `~/.bashrc` пользователя (`source ~/.bashrc`), затем экспортирует `EG_CHARACTER`/`EG_CHARACTER_COLOR` и запускает `fastfetch`;
   * `~/.local/share/konsole/EquestriaOS.profile` — профиль Konsole (файл `.ini`, описывающий один «профиль» терминала: шрифт, цветовую схему, стартовую команду) с `Command=/bin/bash --rcfile <eg_active.bashrc>` — флаг `--rcfile` заставляет bash подгрузить именно этот файл вместо стандартного `~/.bashrc`;
   * правит `~/.config/konsolerc`, выставляя `DefaultProfile=EquestriaOS.profile` — какой профиль Konsole использует для новых окон по умолчанию;
   * через `qdbus` вызывает `org.kde.konsole.Session.setProfile` на всех открытых сессиях — переключает уже открытые окна на новый профиль без перезапуска;
   * дописывает хук в конец `~/.bashrc`, если его там ещё нет — чтобы промпт с именем персонажа появлялся и в терминалах, открытых не через Konsole-профиль напрямую (например, встроенный терминал в другой программе).

## Другие действия

| Действие | Метод (`main.py`) | Что происходит |
|---|---|---|
| Переключатель тёмная/светлая тема | `toggle_dark_light()`, строки 161-165 | Инвертирует `is_dark_mode`, заново вызывает `apply_kde_theme()`. |
| Запуск приложения (детект темы) | `detect_kde_dark_mode()`, строки 150-159 | `kreadconfig6 --file kdeglobals --group Colors:Window --key BackgroundNormal` — по формуле яркости `r*0.299 + g*0.587 + b*0.114` (стандартная формула восприятия яркости человеческим глазом, не собственное изобретение) решает, тёмная тема сейчас или светлая. |
| Первый запуск (нет `state.json`) | `_detect_character_by_accent()`, строки 194-218 | `kreadconfig6 --file kdeglobals --group General --key AccentColor` — пытается угадать, какой персонаж уже был активен, по акцентному цвету. |
| Сохранение выбора персонажа | `_save_state()`/`restore_active_character()`, строки 170-192 | Пишет/читает `~/.local/share/EquestriaOS/Themes/state.json`. Восстановление при старте НЕ применяет тему повторно — только подсвечивает карточку. |
| Редактирование персонажа → «Сохранить» | `save_theme()` → `save_json_and_refresh()`, строка 624 | Пишет весь список персонажей во временный файл и заменяет `characters.json` в `USER_PATH`. |
| «Обзор» для обоев/иконки | `browse_wallpaper()`/`browse_icon()` → `process_picked_folder()`/`process_picked_file()`, строки 640-670 | Копирует выбранный файл/папку в подкаталоги `USER_PATH`, путь в форме становится относительным. |
| Экспорт темы | `export_current_theme()`, строки 221-252 | Собирает `.zip` (модуль `zipfile` стандартной библиотеки Python — просто архив, без внешних утилит) с JSON персонажа, иконкой и всеми обоями. |
| Импорт темы | `import_theme()`/`_import_theme_file()`, строки 254-329 | Распаковывает `.zip`: иконка → в каталог иконок, `wallpapers/*` → в `Wallpapers/`, запись персонажа добавляется в `characters.json`. |
| «Восстановить по умолчанию» | `on_restore_defaults()`, строка 671 | Пересоздаёт список персонажей из системного `characters.json` (перетирает пользовательские правки). |

## Прочее

* Ни одна из вызываемых утилит (`qdbus6`, `kreadconfig6`, `kwriteconfig6`, `plasma-apply-colorscheme`, `fastfetch`) не проверяется на присутствие явно — при отсутствии `run_shell()`/`subprocess.run()` (`main.py:680-681`) просто ничего не делают (ошибки нигде не показываются пользователю), а не крашат приложение.
