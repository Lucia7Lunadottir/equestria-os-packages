# equestria-os-relocator — команды и действия GUI

## Ядро операции (`core.relocate()`, `core.py:47-74`)

Для каждого источника: `shutil.move(src, dest_path)` — функция стандартной библиотеки Python, которая сама решает, как переносить: если источник и назначение на одном разделе — это просто переименование записи в файловой системе (мгновенно, без копирования байт), если на разных — под капотом делает копирование + удаление оригинала. Затем (если `create_symlink=True`, а это всегда так и есть из GUI/бэкенда) — `os.symlink(dest_path, src)`: на месте перенесённого файла/папки создаётся символическая ссылка (файл-указатель) на новое место, так что программы, которые ищут файл по старому пути, найдут его прозрачно. Ошибка перемещения не прерывает обработку остальных источников (собирается список ошибок по каждому).

## Права — только когда реально нужны

* **`privilege.needs_elevation(paths)`** (`privilege.py:25-27`, вызов из `app.py:334`) проверяет `os.access(path, os.W_OK)` для источников и назначения — это системный вызов, который спрашивает у ядра «может ли ТЕКУЩИЙ пользователь писать сюда», а не догадка по владельцу файла. Если всё и так доступно на запись обычному пользователю — операция идёт **без** повышения прав, прямо в GUI-процессе.
* Если хоть один путь не пишется без root — GUI запускает `backend.py` через `privilege.start_elevated()` (`privilege.py:30-37`, вызов из `app.py:90`):
  * элеватор ищется в порядке **`kdesu` → `/usr/lib/kf6/kdesu` → `pkexec`** (`find_elevator()`, `privilege.py:14-18`), берётся первый найденный — `kdesu` (утилита KDE) исторически показывает более привычный для KDE-пользователя диалог, `pkexec` — универсальный вариант polkit, доступный на любом дистрибутиве;
  * запускается: `<elevator> [--] python3 backend.py <src1> [src2 ...] --dest <destination>` (`--` перед аргументами — только для `kdesu`, синтаксис которого требует явного разделителя между своими опциями и командой для запуска; `pkexec` в этом не нуждается);
  * `backend.py` печатает `PROGRESS i total` в stdout построчно (GUI парсит это построчно для прогресс-бара, читая вывод дочернего процесса по мере поступления) и в конце `OK total symlinks` при успехе / текст ошибок в stderr и код выхода 1 при неудаче.

## Другие проверки перед запуском

* **`detect_ntfs()`** (`core.py:6-26`) — читает `/proc/mounts` (виртуальный файл ядра со списком всех точек монтирования и их типов ФС прямо сейчас, обновляется ядром автоматически), находит точку монтирования с максимальным совпадением префикса пути (так определяется, на КАКОЙ именно смонтированной ФС лежит конкретный файл — например, `/mnt/data/file` может оказаться на другой ФС, чем корень `/`), проверяет тип (`ntfs`/`ntfs-3g`/`fuseblk`). Если источник или назначение на NTFS — GUI показывает предупреждение (`_check_ntfs_warning()`, `app.py:289`): символические ссылки — концепция файловой системы Linux/POSIX, NTFS в стандартном режиме монтирования их не поддерживает, поэтому перенос туда/оттуда может завершиться без создания симлинка на исходном месте (сам файл перенесётся успешно, а вот ссылка на старом месте — нет).
* **`_validate_inputs()`** — не даёт запустить перенос, если список источников/назначение пустые.

## Точки входа GUI

| Действие | Что происходит |
|---|---|
| «Обзор» (файл) / «Обзор» (папка) | `QFileDialog.getOpenFileName` / `getExistingDirectory` — стандартные системные диалоги выбора файла/папки Qt. |
| «Переместить» | `_on_relocate_clicked()` (`app.py:324`) → проверка `needs_elevation()` → либо прямой `core.relocate()` в фоновом потоке, либо `privilege.start_elevated()`. |
| Контекстное меню Dolphin «Переместить (Equestria OS Relocator)» | Пункт из `equestria-os-relocator-servicemenu.desktop` (`X-KDE-ServiceTypes=KonqPopupMenu/Plugin` — стандартный механизм KDE «сервисных меню», добавляющих пункты в контекстное меню файлового менеджера) — запускает `equestria-relocator %F` с выделенными в Dolphin файлами как источниками (`%F` — плейсхолдер спецификации `.desktop`-файлов, который Dolphin подставляет списком выделенных путей). |

## Прочее

* Ничего не удаляется без переноса — источник либо становится симлинком (успех), либо остаётся на месте как был (ошибка `shutil.move`).
* Массовое перемещение (несколько источников сразу) обрабатывается по одному в цикле — при ошибке на одном источнике остальные всё равно продолжают обрабатываться, а не прерывают весь батч.
