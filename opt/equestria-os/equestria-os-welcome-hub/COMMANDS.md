# equestria-os-welcome-hub — команды и действия GUI

Один процесс, `pkexec` не используется вообще — только запуск других программ/ссылок и тот же паттерн автозапуска, что в `equestria-os-tutorial`.

## Клик по пункту (`launch()`, `welcome_hub.py:200-214`) — тип запуска зависит от `item.launch_type`

| `launch_type` / признак | Что происходит |
|---|---|
| Ссылка начинается с `steam://store/<app_id>/` | Сначала `pgrep -i steam` — эта утилита ищет среди запущенных процессов по имени (регистронезависимо, `-i`) и возвращает найдены ли; если Steam НЕ запущен, ссылка заменяется на обычную `https://store.steampowered.com/app/<app_id>/`. Причина: протокол `steam://` — это кастомная URL-схема, которую операционная система умеет открывать только если Steam уже установлен и зарегистрировал себя как обработчик; если Steam ещё не запущен, попытка открыть `steam://` может просто ничего не сделать или запустить сам Steam без перехода к нужной странице — обычная веб-ссылка на steampowered.com работает в любом случае. |
| `launch_type == "url"` или цель начинается с `http` | `subprocess.Popen(["xdg-open", target])` — `xdg-open` — стандартная freedesktop-утилита «открой это тем, что настроено по умолчанию для этого типа ссылки/файла» (для `http://` — браузер по умолчанию, для `.pdf` — PDF-читалка и т.д.), сама программа не решает, каким конкретно браузером открывать. |
| `launch_type == "command"` | `subprocess.Popen(["/bin/bash", "-c", target])` — цель выполняется как полноценная shell-команда (в отличие от простого запуска бинарника, здесь можно использовать пайпы, переменные окружения и т.п.). |
| Всё остальное | `subprocess.Popen([target])` — прямой запуск бинарника без аргументов, без промежуточного shell. |

Список пунктов (музыкальные YouTube-каналы фандома, Reddit, фанатские игры, Equestria Net и т.д.) — статические данные внутри `welcome_hub.py`, ничего не подгружается по сети при открытии приложения.

## Переключатель «Запускать при входе в систему» (`setup_autostart_logic()`/`toggle_autostart()`, `welcome_hub.py:217-252`)

Идентичная логика `equestria-os-tutorial` (тот же стандарт XDG autostart, см. подробное объяснение механизма в `equestria-os-tutorial/COMMANDS.md`):
* Путь: `~/.config/autostart/equestria-welcomehub.desktop` (переопределяет глобальный `/etc/xdg/autostart` для этого пользователя).
* Файла нет → считается включённым по умолчанию (наследуется от глобального автозапуска).
* Переключение пишет `.desktop`-файл целиком с `Exec=equestria-os-welcome` и `Hidden=true`/`Hidden=false`.

## Прочее

* Никаких системных файлов вне `~/.config/autostart/` не трогает.
* `pgrep`/`xdg-open`/`bash` — единственные внешние команды; отсутствие любой из них просто приведёт к ошибке запуска конкретного пункта (исключение при `subprocess.Popen`, если бинарь не найден), не крашит всё приложение целиком.
