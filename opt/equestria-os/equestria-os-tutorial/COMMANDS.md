# equestria-os-tutorial — команды и действия GUI

Один процесс, никакого `pkexec` — только запуск других приложений и переключатель автозапуска в домашнем каталоге пользователя.

## Кнопки «Открыть <приложение>» на слайдах → `launch_app(desktop_filename)` (`main.py:377-403`)

Каждая кнопка привязана к конкретному `.desktop`-файлу из `/usr/share/applications/`:

| Слайд | Кнопка | `.desktop` |
|---|---|---|
| 2 | «Персонажи» / «Панель задач» | `equestria-theme-switcher.desktop`, `equestria-os-task-panel-changer.desktop` |
| 3 | «Магазин приложений» | `equestria-os-software-center.desktop` |
| 4 | «Менеджер пакетов» | `equestria-os-package-manager.desktop` |
| 5 | «Relocator» | `equestria-os-relocator.desktop` |
| 6 | «Службы» / «Swap» / «Диски» | `equestria-os-services-manager.desktop`, `equestria-os-swap-manager.desktop`, `equestria-os-disk-manager.desktop` |
| 7 | «Welcome Hub» | `equestria-os-welcome.desktop` |

Механика запуска: читает поле `Exec=` из `.desktop`-файла **напрямую** построчным парсингом (не через штатный лаунчер `xdg-open`/`gtk-launch`, которые тоже умеют разбирать `.desktop`-файлы, но здесь сделано вручную), вычищает плейсхолдеры (`%F`, `%U`, `%u` и т.п. — это часть спецификации Desktop Entry: подстановки, которые файловый менеджер обычно заменяет на переданные файлы/URL; здесь запуск идёт без файлов, поэтому они просто вырезаются), затем `subprocess.Popen(shlex.split(cmd), start_new_session=True)`. `shlex.split` разбивает командную строку на список аргументов так же, как это сделал бы сам shell (с учётом кавычек), не выполняя её через `bash -c` — безопаснее и предсказуемее для строки, пришедшей из файла. `start_new_session=True` — запускаемый процесс получает **новую сессию** (в Unix-терминологии — группу процессов, отвязанную от родительской), поэтому закрытие окна тура не приведёт к автоматическому закрытию (`SIGHUP` и подобные сигналы) запущенного приложения, как это случилось бы для обычного дочернего процесса.

Если файл `.desktop` не нашёлся или парсинг `Exec=` не удался (строка не начинается с `Exec=` ни на одной строке файла) — запасной вариант `kioclient exec <path>` — `kioclient` — консольная утилита KDE, которая умеет то же самое, что штатный обработчик `.desktop`-файлов в KDE, как более надёжный, но и более «тяжёлый» путь.

## Переключатель «Запускать при входе в систему»

* **Путь состояния:** `~/.config/autostart/equestria-os-tutorial.desktop` (`_autostart_path()`, `main.py:342-344`).

> **Механизм XDG autostart** — открытый стандарт freedesktop.org: любая программа, которая должна запускаться при входе в графическую сессию, кладёт свой `.desktop`-файл в `/etc/xdg/autostart/` (для всех пользователей) или в `~/.config/autostart/` (для одного конкретного пользователя — файл с тем же именем **переопределяет** глобальный, а не дополняет его). Ключ `Hidden=true` в пользовательской копии — специально предусмотренный спецификацией способ сказать «не запускать это для меня», не трогая и не удаляя саму глобальную установку (это важно: удаление файла из `/etc/xdg/autostart/` при переустановке пакета вернуло бы автозапуск, поэтому вместо удаления используется именно `Hidden=true`).

* **Если файла нет** (`_autostart_enabled()`, `main.py:346-358`) — тур считается включённым (`_autostart_enabled()` возвращает `True`) — значит пользовательская копия ещё не создавалась, автозапуск идёт по умолчанию из `/etc/xdg`.
* **Включить/выключить** (`_set_autostart()`, `main.py:360-375`) — пишет полный `.desktop`-файл с `Hidden=false` (разрешить) или `Hidden=true` (полностью заблокировать, даже если глобальная копия существует).

## Прочее

* Ни один файл вне `~/.config/autostart/` не создаётся и не редактируется этим приложением.
* Локализация — свой встроенный загрузчик переводов, ничего внешнего не запускает.
